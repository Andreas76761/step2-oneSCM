**Vega i155 – Fehlerbehandlung bei der Erzeugung**

Bei der Erzeugung der i155-Datei für Vega führt oneSCM automatisch Prüfungen gemäß der zugehörigen Dokumentation durch. Im Fokus stehen dabei die Satzarten RC01, RC05 und RC20, die zu den verpflichtenden Satzarten der i155-Schnittstelle gehören: Satzart 01 (Header mit Steuerinformationen), Satzart 05 (Vertragsstammdaten) und Satzart 20 (Deckung bzw. Coverage, wobei mehrere Instanzen vorkommen können). Für jede Satzart werden zunächst Ländercode und Vertragsnummer ermittelt. Ist die Servicevertragsnummer nicht gefüllt, wird der Fehler „Service contract number is missing“ erzeugt.

Für Satzart 05 werden darüber hinaus zahlreiche inhaltliche Prüfungen durchgeführt. Die Zeilenlänge muss bei Satzart 01 genau 133 Zeichen und bei den Satzarten 05 und 20 jeweils genau 4000 Zeichen betragen, andernfalls wird „row length is not ok“ gemeldet. Es wird geprüft, ob eine FIN/VIN vorhanden ist („FIN/VIN is missing“). Vertragsbeginn, geplantes Vertragsende, Eliminierungsdatum und Datum der Statusänderung müssen jeweils ein gültiges Datum im Format JJJJMMTT sein, sonst erscheint die jeweilige Meldung, etwa „Contract start date is not valid“. Zusätzlich werden die Datums- und Kilometerangaben auf Plausibilität geprüft: Liegt das geplante Vertragsende oder das Eliminierungsdatum vor dem Vertragsbeginn, wird ein Fehler erzeugt. Dasselbe gilt, wenn die Start-Laufleistung nicht kleiner als die geplante End-Laufleistung beziehungsweise die Eliminierungs-Laufleistung ist. Die Eliminierungs-Laufleistung und die geplante End-Laufleistung dürfen weder 0 noch leer sein („Elimination mileage is not valid“ bzw. „End planned mileage is not valid“). Fehlt der Coverage Code, der Vertragstyp oder der Vertragsstatus, wird dies ebenfalls als fehlend gemeldet („Coverage code is missing“, „Contract type is missing“, „Contract status is missing“).

Für Satzart 20 wird geprüft, ob die folgenden Angaben vorhanden sind: Coverage ID, Start-Laufleistung der Deckung, geplante End-Laufleistung, tatsächliche End-Laufleistung, Startdatum, geplantes Enddatum und tatsächliches Enddatum der Deckung. Fehlt eine dieser Angaben, wird die entsprechende Meldung, beispielsweise „Coverage ID is missing“, ausgegeben.

Alle nicht erfüllten Bedingungen werden in einer Log-Datei festgehalten. Diese wird für jede i155-Datei erzeugt und heißt nach dem Schema i155_VegaCountryCodeCountryCodeISO3166_LogFile_JJJJMMTTHHMM, zum Beispiel i155_20000DE_LogFile_202308141700.xlsx. Sie liegt im Format xlsx vor und enthält je Eintrag die laufende Nummer, den Ländercode, die Vertragsnummer und die Meldung. Treten bei der Erzeugung keine Fehler auf, bleibt die Log-Datei leer. Die Log-Datei wird per E-Mail über eine generische E-Mail-Adresse an den MPC-Benutzer des jeweiligen Marktes versendet. Verträge, bei deren Verarbeitung Fehler aufgetreten sind, werden markiert und automatisch in die nächste Erzeugung der i155-Datei einbezogen.

**Vertragsstatus – Bestätigung durch das Backend**

Über die API konnten Verträge bisher auf unterschiedliche Status gesetzt werden. Künftig dürfen die Status „Waiting for Activation“ und „Active“ ausschließlich durch das Backend gesetzt werden. API-Benutzer haben keine Möglichkeit mehr, diese Status zu beeinflussen. Damit wird verhindert, dass ein API-Benutzer einem Vertrag ohne Prüfung und Bestätigung einen dieser beiden Status zuweist. Weitere Informationen zum Statusmodell sind in der Confluence-Dokumentation „Contract Status Model“ zu finden.
