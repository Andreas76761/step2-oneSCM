Der Auslösemechanismus für die Erzeugung des Data Products wurde angepasst und richtet sich nun nach einem festgelegten Stichtag, dem 3. des Monats. Zuvor musste bei den Legacy-Märkten abgewartet werden, bis das Unified Data Model (UDM) für alle Märkte eines Laufs aktualisiert war, bevor das Data Product erstellt wurde. Jetzt läuft der Data-Product-Job ausschließlich zum festgelegten Datum. Liegen bis dahin nicht alle Dateien vor, wird für die betroffenen Märkte eine Benachrichtigung versendet, und es werden die zuletzt im UDM gespeicherten Daten verwendet. Trifft eine Datei nach dem Stichtag ein, wird das UDM aktualisiert, das Data Product jedoch nicht neu ausgelöst. Dasselbe gilt, wenn eine neue Datei eintrifft, während der Data-Product-Job bereits läuft. Bei oneSCM erfolgt die Aktualisierung des UDM am Ersten des Monats, sodass diese Daten beim Start des Jobs bereits vorliegen.

Die Benachrichtigungen zum Data Product wurden von den bestehenden Benachrichtigungen getrennt und werden über einen eigenen Verteiler versendet. Empfänger sind die Konsumenten und/oder die Data-Product-Verantwortlichen. Eine Benachrichtigung erfolgt, wenn die Erstellung des Data Products fehlschlägt. Wird das Data Product erfolgreich erstellt, fehlen aber Daten einzelner Märkte, wird eine Nachricht mit einer Liste der betroffenen Märkte verschickt. Wurde das Data Product erfolgreich und ohne fehlende Daten erstellt, wird keine Benachrichtigung versendet.

Neu eingeführt wurde die Integration von ISP-Daten in Form eines eigenen Data Products. Dafür wird die VEGA-I131-Datei importiert, die die Daten aller VEGA-Märkte in einer einzigen Datei enthält. Berücksichtigt werden alle Märkte mit Ausnahme der Daten aus dem Lkw- und Busgeschäft; Daten von VEGA-Ländern aus diesen Bereichen werden ignoriert. Die Dateien treffen wöchentlich als Delta-Datei ein, für zurückliegende Dateien erfolgt eine vollständige Ladung. Zur Ablage der ISP-Daten kann je nach Anwendungsfall eine eigenständige Tabelle innerhalb oder außerhalb des UDM verwendet werden. Das Data Product wird bereitgestellt, sobald eine I131-Datei eingeht, und enthält die ISP-Daten aller verfügbaren Märkte in einer Datei.

Der Schlüssel des ISP-Data-Products besteht aus der Fahrzeugidentifikationsnummer (FIN) und dem ISP-Code. Die Sparte (Division) wird aus der FIN abgeleitet, und für unbekannte oder neue Baureihencodes ist ein Fehlerprotokoll oder eine vergleichbare Information vorgesehen, damit diese in der Zuordnungstabelle ergänzt werden können. Wird eine neue Kombination aus FIN und ISP-Code geliefert, wird der Datensatz gemäß Definition des Data Products eingefügt; bei einer bereits vorhandenen Kombination wird der Datensatz aktualisiert. Die Delta-Datei enthält dabei nur geänderte oder hinzugefügte Codes eines Fahrzeugs.

Das Data Product enthält aktuelle, vollständige und konsistente Daten, einschließlich aller vergangenen Perioden, im definierten Format. Es umfasst alle verfügbaren ISP-Märkte außer Bus- und Lkw-Märkten, unabhängig davon, ob diese in oneSCM oder in den Legacy-Anwendungen (SC Legacy) vorliegen. Der Import neuer Periodendaten führt zu einem aktualisierten, konsistenten Data Product. Die Bereitstellung erfolgt in einem S3-Bucket im Hyperion Data Hub, im gleichen Datenformat wie die übrigen Data Products der Datenbasis. Über Erfolg oder Fehlschlag der Erstellung wird benachrichtigt. Vor dem Schreiben neuer Daten wird eine Sicherung des Data Products angelegt, aus der es im Fehlerfall wiederhergestellt werden kann. Zudem ist eine Fehlerbehandlung für die Delta-Bereitstellung umgesetzt, die inkonsistente oder fehlende Daten verhindert.
