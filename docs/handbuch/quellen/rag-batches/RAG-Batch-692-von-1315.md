**Supplier Cost Report (Kostenbericht für Lieferanten)**

Der Supplier Cost Report zeigt einem Lieferanten, welche Schadenkosten an ihn weitergeleitet wurden. Die Kosten werden auf Ebene des Schadencodes zusammengefasst. Sobald ein Schadenfall verarbeitet wird, sei es über den Import von I156/Vega oder über eine manuelle Werkstattrechnung, und der zugehörige Coverage Code die Kostenstelle „Supplier“ hat, werden die Kosten als SCIN an den Lieferanten weitergeleitet. Der Bericht bündelt diese weitergeleiteten Kosten. So können der Lieferant oder, je nach Konfiguration des Empfängers, der MPC genau nachvollziehen, was ihm pro Vertrag, pro Schadenfall und pro Schadencode in Rechnung gestellt wird. Dies ist besonders für Lieferanten relevant, deren Kosten über SCIN weitergeleitet werden, etwa Versicherer oder Rückversicherer wie RealGarant. Sie erhalten Transparenz über die Kosten, ohne von einzelnen Arbeits- und Materialpositionen überfrachtet zu werden.

Als globale Standardebene dient der Schadencode. Pro Schadenfall wird eine Zeile je eindeutiger Kombination aus Coverage Code und Schadencode bzw. Schadendefinition erzeugt. Dabei gilt dieselbe Aufteilungsregel wie bei der Erzeugung von Rechnungspositionen, es wird keine neue Regel eingeführt. Der Bericht wird erzeugt, wenn die SCIN-Rechnungen per Batch-Job exportiert werden. Er wird pro Lieferant und Coverage Code erstellt.

Der Berichtsinhalt ist nicht marktspezifisch fest vorgegeben. oneSCM stellt sämtliche auf Rechnungsebene gespeicherten Daten als Druckvariablen bereit, unabhängig davon, ob sie für einen Revenue Report oder einen Cost Report genutzt werden. Jeder Markt legt das Template des Berichts selbst fest, indem er die benötigten Spalten auswählt und anordnet. Für jeden Lieferanten wird das in der Lieferantenverwaltung hinterlegte Template verwendet. Gerendert werden nur die Druckvariablen, die im jeweiligen Template ausgewählt sind. Das Layout kann sich daher von Markt zu Markt unterscheiden, obwohl dieselben Daten zugrunde liegen. Ein Beispiel für einen Berichtskopf für RealGarant enthält unter anderem die Felder externalId, tenant, supplier, damageCode, damageCode_designation, damageDefinition, damageType_designation, die Netto-Beträge für Arbeit, Teile und Fremdleistungen in Mandantenwährung, invoiceDate, firstRegistrationDate, fin, repairDate, repairMileage, mileageUnit, amountNetInTenantCurrency, amountNetAcceptedInTenantCurrency, serviceContract, coverageCode, processingNumber, iconReferenceNumber, dealerNumber und vin.

Bei jedem Lauf wird der Bericht sowohl als CSV- als auch als XML-Datei erzeugt, beide mit identischen Daten. Die Auslieferung erfolgt an den Empfänger, der je Berichtstyp in der Lieferantenverwaltung konfiguriert ist. Ist der Lieferant als Empfänger hinterlegt, erhält er den Bericht direkt. Ist der MPC hinterlegt, geht der Bericht zunächst an den MPC, der ihn anreichern und an den Lieferanten weiterleiten kann. Der Bericht wird in der für den Lieferanten konfigurierten Sprache erstellt. Beschreibungen von Schadencodes und Schadenarten sowie die Berichtsbeschriftungen erscheinen dann in dieser Sprache. Welche Rollen den Bericht nutzen dürfen, richtet sich nach den definierten bzw. neuen Rollen.

**Aktualisierte Regeln bei mehrfachen Entscheidungen zu Vega-Schadenfällen**

Für den Import von I156-Dateien aus Vega gilt eine angepasste Regel für den Umgang mit mehreren Entscheidungen zum selben Schadenfall und Schadencode. Zuvor wurden Entscheidungen mit gleicher Entscheidungsnummer, aber unterschiedlichem Credit-Run-Datum in der Datenbank wie zwei getrennte Fälle behandelt. Dadurch wurden die Daten in den Finanzdokumenten von oneSCM nicht korrekt aktualisiert.

Nun wird die Entscheidungsnummer mit der zuvor gespeicherten verglichen. Ist sie gleich oder höher, überschreibt die neue Entscheidung die bestehenden Daten in der Datenbank. Dies gilt auch, wenn die Nummern nicht lückenlos aufeinanderfolgen, etwa bei Folgen wie 1, 1, 3 oder 1, 2, 2, 2, 5. Ist die Entscheidungsnummer dagegen niedriger als die zuvor gespeicherte, wird der Schadenfall nicht importiert, und es wird eine entsprechende Fehlermeldung angezeigt. Auf diese Weise ist in oneSCM stets die jeweils neueste Entscheidung zu einem Schaden an einem Schadenfall hinterlegt.
