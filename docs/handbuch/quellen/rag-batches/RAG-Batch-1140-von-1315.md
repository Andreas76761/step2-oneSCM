**Produkthistorisierung: Preise in der Vergangenheit (Contract Calculation)**

Mit der Produkthistorisierung können Marktnutzer (MPC) in den Divisionen PC und VAN ein bestehendes Produkt ändern, ohne es vorher deaktivieren zu müssen. Bisher gab es keine Produktversionen: Wer Änderungen vornehmen wollte, musste das Produkt deaktivieren, wodurch es in dieser Zeit nicht verkauft werden konnte. Künftig legen Sie stattdessen eine neue Version desselben Produkts an, ändern deren Daten, weisen eine Preisversion zu und lassen die Version automatisch veröffentlichen. Historische Daten bleiben dabei erhalten. Das System speichert jede Version und greift bei Bedarf darauf zurück, etwa bei Prolongationen und bei MBLD-Preisen aus der Vergangenheit.

Eine neue Version kann nur von einem Produkt mit dem Status „Published“ oder „Deactivated“ aus erstellt werden. Ein solches Produkt besitzt bereits die Version 1. Die Versionsnummern werden automatisch fortlaufend vergeben (V1, V2 usw.). Die neue Version erhält ein von Ihnen gewähltes neues Änderungsdatum („Effective Modification“). Die Vorgängerversion wird gemäß den Historisierungsregeln zum Tag vor diesem neuen Startdatum geschlossen. Der Zusammenhang der Produkthistorie bleibt erhalten. Der Versuch, eine neue Version aus einer Version im Status Draft, Created, Ready oder Deleted zu erstellen, wird abgelehnt. Es darf zudem nur eine nicht aktive Version gleichzeitig existieren; solange etwa V2 noch im Entwurf ist, kann keine V3 angelegt werden, und das System weist darauf hin. Zusätzlich gibt es in der Produktübersicht eine neue Spalte „Effective Modification“.

Bei einem veröffentlichten Produkt bleibt die bisherige Bearbeiten-Aktion erhalten, mit der sich nur Produktname, Produktbeschreibung, zusätzliche Informationen und Bild ändern lassen. Daneben steht ein Aktionsmenü mit den Einträgen „Edit This Version“, „Deactivate“, „Manage Prices“, „Manage T&C“ und „Delete“. „Manage Prices“ und „Manage T&C“ sind mit einem grünen Haken markiert, sobald sie erledigt sind. „Deactivate“ ist nur sichtbar, wenn das Produkt veröffentlicht ist. Die Versionsdetails zeigen Status, Startdatum und Enddatum. Das Startdatum von Version 1 entspricht dem Start der ersten Preisversion, das einer neuen Version dem Start der ihr zugewiesenen Preisversion. Das Enddatum richtet sich nach der zugewiesenen Preisversion.

Im Bearbeitungsablauf durchlaufen Sie die Produkt-Schritte. Schritt 1 (Blueprint-Setup) bleibt unverändert. In Schritt 2 (Basisinformationen) kann die gesamte Kette der Produktversion geändert werden. In Schritt 3 (Vertriebs- und Vertragskonfiguration) kann alles geändert werden. Wichtig: Wenn sich Vega-Codes bzw. Branchencodes ändern, muss die Branche (die Liste der anwendbaren Branchen im Produkt-Setup) aktualisiert werden. Schritt 4 (Deckungen) bleibt unverändert. Wenn Änderungen in Schritt 3, 5 (Preismatrix) oder 6 (Fahrzeugvoraussetzungen) Auswirkungen auf nachgelagerte Konfigurationen wie Preise oder Fahrzeugvoraussetzungen haben, erscheint beim Klick auf „Weiter“ ein Hinweis. In Schritt 7 (Produktzusammenfassung) sehen Sie die neue Version bereits im richtigen Status und können zwischen den Reitern wechseln. Über die Aktionsschaltfläche können Sie die Geschäftsbedingungen (T&C) ändern; die geänderten T&C gelten dann für das gesamte Produkt. Außerdem müssen Sie Preise zuweisen, damit die automatische Veröffentlichung erfolgen kann. Die Änderungshistorie zeigt alle Änderungen in sämtlichen Status, über alle früheren und aktuellen Versionen hinweg.

Eine Version durchläuft die Status Draft, Created, Ready, Published und Deprecated, die jeweils farblich gekennzeichnet sind. „Draft“ bedeutet mindestens eine Änderung an der Version. „Created“ bedeutet, dass eine Preisversion ohne Cluster vorhanden ist, „Ready“, dass eine Preisversion mit Cluster vorhanden ist. „Published“ bedeutet, dass Preisversion und Cluster freigegeben sind. „Deprecated“ bedeutet, dass keine Änderungen mehr möglich sind; dieser Status tritt ein, sobald eine andere Version veröffentlicht wird. Wird also V2 veröffentlicht, wechselt V1 automatisch auf „Deprecated“. Es ist immer nur eine Version eines Produkts veröffentlicht.

Nach der Aktualisierung vom 01.10.2026 sind für den Versionslebenszyklus nur folgende Übergänge zulässig: von Draft zu Created oder Deleted, von Created zu Ready oder Deleted, von Ready zu Published oder Deleted, von Published zu Deactivated sowie von Deactivated zu Published. Jeder andere Übergang wird abgelehnt und verändert die Produktversion nicht.

Die Aktion „Bearbeiten“ für die vollständige Produktversion steht nur in den Status Draft, Created und Ready zur Verfügung. Für Published, Deactivated und Deleted ist sie in der Oberfläche ausgeblendet, und ein entsprechender Versuch wird auch vom Backend abgelehnt. Unabhängig davon gibt es die Aktion „Metadaten bearbeiten“. Sie steht in jedem Produktstatus zur Verfügung, also auch bei Published, Deactivated und Deleted, und macht die Version nicht insgesamt bearbeitbar. In der Produktübersicht führen sowohl „Bearbeiten“ als auch „Ansehen“ auf dieselbe Produktdetail- bzw. Versionsseite.

Die automatische Veröffentlichung gilt ab Version 2. Sie erfolgt erst, wenn die zugewiesene Preisversion freigegeben ist und die vorherige Produktversion veröffentlicht ist. Ist eine der beiden Bedingungen nicht erfüllt, wird nicht automatisch veröffentlicht. Status und Daten früherer Versionen bleiben davon unberührt. Ohne zugewiesene Preise fehlt bei „Manage Prices“ der grüne Haken, und die Veröffentlichung ist nicht möglich. Die erste Produktversion wird immer manuell in der Oberfläche veröffentlicht.

Die Versionsdaten werden im Backend gespeichert und bei Generierung und Verwaltung im Payload übermittelt. Die Version ist mit der Preisversion verknüpft. Auswirkungen auf Prolongationen sind zu berücksichtigen. Sie werden bei Preisänderungen stets benachrichtigt, wenn diese Auswirkungen haben. Sobald die Epic zur Ergänzung eines nicht-BASE-COV-Codes im bestehenden Blueprint umgesetzt ist, verwendet „Edit This Version“ immer die aktuellsten Blueprint-Daten.

Ein typischer Ablauf sieht so aus: Sie öffnen ein veröffentlichtes Produkt in Version 1 und wählen „Edit This Version“. Das System legt Version 2 im Status Draft an. Sie ändern Branchencodes und Deckungen, weisen T&C und Preise zu, und anschließend ist Version 2 veröffentlicht und Version 1 auf „Deprecated“ gesetzt.
